# 迭代 4：CIVC 自评审计报告

## 审计对象
- 项目：Soft-Engineering（Python 文字 MUD）
- 审计范围：当前仓库开发与 AI 辅助编码流程
- 框架：CIVC 四阀门（Constraint / Inform / Verify / Correct）

---

## C（Constraint）约束阀门

### 现状
- AI 可访问：仓库内源码、测试、文档文件。
- AI 可修改：本地工作区文件（未做细粒度目录白名单）。
- Git 分支存在，但尚未强制“受保护分支 + 必须 PR 合并”。
- 没有真正沙盒隔离（仍在开发机本地直接运行）。

### 风险
- 误改核心文件后可能直接进入主分支。
- 缺少“高风险操作阻断”机制（如误删文件、危险 git 命令）。

### 改进方案
1. 启用分支保护：`main/develop` 禁止直推，必须 PR + CI 通过。
2. 增加 AI 工作规则：仅允许改动 `src/`、`tests/`、`docs/`，其余目录默认只读。
3. 在团队流程中明确禁止破坏性命令（reset --hard/force push）。
4. 条件允许时将 AI 运行迁移到容器化开发环境（最小权限挂载）。

---

## I（Inform）告知阀门

### 现状
- 已有 `README.md` 说明架构、模块关系、运行方式。
- 本次新增 `AGENTS.md`，包含目录职责、编码约束、禁止操作清单。
- 仍缺少“关键业务规则索引”（如战斗恢复规则、拾取例外规则）统一入口。

### 风险
- 新接入 AI 助手若未完整阅读源码，可能误解规则并生成不一致代码。

### 改进方案
1. 在 `docs/` 新增“核心规则速查表”（命令语义、战斗规则、掉落规则）。
2. 在 `AGENTS.md` 持续维护“新增模块接入说明”。
3. 每次迭代在 PR 模板中增加“上下文是否同步更新”检查项。

---

## V（Verify）验证阀门

### 现状
- 已接入 `pytest` 与 GitHub Actions CI。
- 本次补充核心 API Mock 单元测试，核心模块覆盖率约 87.7%（>= 80%）。
- 总体覆盖率约 74%，`game_engine.py` 交互主循环覆盖较低。

### 风险
- 交互驱动代码回归可能漏检（输入循环、异常流程等）。

### 改进方案
1. 继续拆分 `GameEngine` 可测逻辑（解析/状态切换）并补单测。
2. 增加 smoke 测试：模拟最短游戏流程（启动 -> 指令 -> 退出）。
3. 在 CI 增加核心模块覆盖率阈值检查（未达标则失败）。

---

## C（Correct）纠正阀门

### 现状
- 使用 Git 可回滚（`git revert` / 分支回退），但尚无“一键回滚脚本”。
- 没有标准化“故障回滚 Runbook”。

### 风险
- 出错时依赖个人经验回滚，恢复效率不稳定。

### 改进方案
1. 提供 `scripts/rollback.ps1`（或文档化命令集）实现快速回退到上一个稳定提交。
2. 在 `docs/` 增加“故障处理手册”：定位 -> 回滚 -> 验证 -> 再发布。
3. 发布前打轻量 tag（如 `release-iter4`），便于快速锚定稳定点。

---

## 综合结论
- 本项目在 Inform 与 Verify 阀门已有明显提升（`AGENTS.md` + 核心测试覆盖率达标）。
- 当前最薄弱阀门为 Constraint 与 Correct，建议优先落地“分支保护 + 回滚脚本 + 流程文档”。
- 按上述改进执行后，可将 AI 辅助开发从“可用”提升到“可控、可追溯、可恢复”。
